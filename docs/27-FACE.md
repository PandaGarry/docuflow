# Лицо: глаза, рот, мимика

Как устроена «живость» лица. Модуль — `studio/engine/facefx.py`.

## Принцип: база + слои, а не генерация каждого кадра

Каждый новый кадр от генератора немного другое лицо, поэтому мимику нельзя
«перегенерировать на каждый звук» — лицо поплывёт. Схема как в 2D-сериалах:

| что | откуда берётся |
|---|---|
| база кадра | `emotions/<эмоция>.png` (готовый портрет) |
| моргание | `emotions/eyes-closed.png` + опускание века |
| взгляд | сдвиг зрачка внутри глаза |
| речь | `visemes/<форма>.png`, из них берутся только губы |
| дыхание | микросдвиг всей головы по синусу |

## Разметка лица по ракурсам (обязательна)

Автопоиск зрачков по тёмным пятнам **не работает** на этих портретах: в тёмные
пятна попадают брови и борода, «межзрачковое расстояние» гуляло от 16 до 400 px.
Поэтому лицо размечается один раз руками и лежит в
`studio/2p5d/<персонаж>/face.json` — **отдельно для каждого ракурса**:

```
front:          глаза L(0.368, 0.262) R(0.625, 0.262), рот (0.499, 0.364)
three-quarter:  глаза L(0.355, 0.208) R(0.517, 0.205), рот (0.385, 0.303)
side:           глаз (0.792, 0.248), рот (0.860, 0.368)   — видна одна сторона
```

**Важно:** доли считаются не от размера картинки, а от **рамки содержимого**
(bbox непрозрачных пикселей). Кадры приходят разного размера (768×1400,
768×1390, 681×1385), и доли от картинки давали промах на пол-лица: разметка
попадала на щёку вместо глаза. Функция — `facefx.portrait_bbox`.

Проверка: `facefx.landmarks_px(lm, img)` → нарисовать кружки и прямоугольники
на кадре 1:1 и посмотреть глазами, что они на месте. Делать это надо именно на
кропе 1:1 — на уменьшенном превью координаты читаются с ошибкой в 5–10 %.

Разметка — часть канона: меняется только при смене персонажа или ракурса.
Проверка глазами: наложить прямоугольники на кадр
(`facefx.landmarks_px` → нарисовать) и посмотреть, что глаза накрыты точно.

## Моргание

`facefx.blink(base, closed, lm, amount)`:
- `amount=0` — открыто, `1` — закрыто;
- не смешивать кадры: полупрозрачное наложение двух разных век даёт смаз;
- веко «напускается» сверху вниз вертикальной маской с мягкой границей;
- маска ограничена овалом глаза, поэтому брови и борода не меняются.

Результат проверен: 0 / 0.35 / 0.7 / 1.0 читаются как естественное смыкание.

## Речь (виземы)

Формы для русского: `rest, A, E, I, O, U, M, F, S`.
`facefx.morph_mouth(base, viseme_img, lm)`:
- берём из визема **только изменившиеся пиксели** (разность кадров выше
  порога), а не овал целиком;
- иначе вокруг рта видно кольцо: генератор рисует слегка другое лицо;
- маска дополнительно ограничена овалом вокруг рта по разметке, край сглажен.

Проверено: 5 кадров (база + М, Э, А, О) — рот меняется, лицо остаётся тем же.

## Промпт портрета: рамка задаётся отдельно

Кадры лица нельзя просить общим шаблоном кадра позы: там сказано «вся фигура
от волос до обуви», а нам нужен портрет. Первая попытка с обоими требованиями
в одном промпте дала в одном наборе мелкие фигурки в полный рост, крупные лица
и горизонтальные кадры 1408×768 — всё это пришлось выбросить.

Теперь в `characters.py` есть `PORTRAIT` (вертикальный кадр, по грудь, голова
≈65 % высоты) и `portrait_prompt(char, action, view)`; ракурс — параметр, а не
приклеенный «front view». Проверка после генерации: все кадры набора должны
быть одного размера и одного масштаба лица.

## Проверка и подгонка набора

- `studio/tools/portrait_check.py <char>` — ищет брак в наборе: горизонтальный
  кадр, «фигурку в полный рост» вместо лица (заполнение кадра), разный масштаб
  лица (межзрачковое расстояние). Существующие наборы папы проходят: 0 к
  пересъёмке, заполнение 0.98–1.00.
- `studio/tools/fit_portrait.py <char> [--write]` — приводит кадры набора к
  одному масштабу: режет по альфе, масштабирует по глазам (или по высоте
  содержимого) и ставит на холст 768×1400. На готовых наборах это no-op
  (масштаб x1.00), на свежих кадрах — выравнивание.

## Как генерировать визем: только по референсу

Проверено на практике: набор виземов нельзя собирать генерацией «с нуля» по
тексту, даже с точной рамкой. В одном наборе приходят разные компоновки —
по грудь, по плечи, крупный план, — и после любой автоподгонки рот оказывается
не там, где рот базы. Пробовал два автоматических способа выравнивания:

- **по цвету кожи** (самая крупная связка «кожаных» пикселей): ломается на
  кадре с открытым ртом — область сливается с шеей, масштаб выходит x1.4–2.5
  вместо x1.0;
- **по оптическому потоку** (`estimateAffinePartial2D` по сетке векторов):
  на уже почти совпадающих кадрах даёт почти единичное преобразование, но
  чужую компоновку не вытягивает — терять нечего, а рот всё равно не там.

**Правило:** визем генерируется как правка базового кадра — на вход подаётся
изображение базы (`images=[<вид>/rest.png]`) с просьбой «ничего не менять,
только форма рта». Тогда рамка, масштаб и положение лица совпадают по
построению, и `morph_mouth` берёт только изменившийся рот.

Пост-подгонка (`fit_portrait.py`) остаётся для мелочи: выровнять масштаб у
похожих кадров. Чужой ракурс и чужую компоновку она не лечит.

## Ограничения, которые надо помнить

1. **Только фронт.** При повороте головы больше ~15–20° разметка лица не
   совпадает с картинкой, и моргание с ртом поедут. Для профиля нужны свои
   базы и своя разметка.
2. **Голова должна быть в одном масштабе.** В портретах эмоций `head_w`
   отличается (537…710), поэтому вклеивать мимику в полный рост надо с
   масштабированием по `ipd`, а не по ширине головы.
3. **Рот и моргание независимы** — можно моргать во время речи, слои не
   конфликтуют (разные области).

## Что дальше по лицу

1. Добить виземы `I, U, F, S, rest` (в работе).
2. Собрать тестовый клип: «нейтрально → моргание → фраза из 4 виземов»,
   посмотреть стыки на 12–15 fps.
3. Проверить, как это работает поверх тела (поза + вклеенная голова):
   понадобится маска шеи и подгонка по `ipd`.

## Контроль кадров мимики

```
python studio/tools/qa_mimic.py dad     # → studio/out/qa-mimic.md
```

Сверяет каждый кадр с нейтральным портретом своего ракурса: масштаб головы
(±12 %), высоту содержимого (±6 %), срезанную макушку, остатки зелёного фона,
пустой кадр. Код выхода 1, если есть замечания.

**Ошибка, которую эта проверка уже поймала в самой себе:** нельзя проверять
цвет в углах обрезанного кадра. После `trim` углы кадра — это плечи персонажа.
Проверка работает по сырому файлу.

**Что метрики не ловят:** «уплывшую» причёску и форму бороды. Два кадра из
этой серии прошли по числам, но лицо на них нарисовано другое. Поэтому каждый
новый кадр дополнительно смотрится глазами листом 6×N.

## Ещё нужны кадры состояния (не входят в список эмоций)

`eyes-closed` — отдельно для КАЖДОГО ракурса, иначе моргание работает только
во фронте. Лежат рядом с эмоциями: `emotions/<ракурс>/eyes-closed.png`.

## Причёска: единственное, что «плывёт»

Замер (`qa_mimic`): IoU силуэта волос относительно нейтрального портрета
ракурса. Норма — от 0.85; у нас от 0.73 до 1.00, пять кадров ниже порога.

Что пробовали и почему отказались:
- перенос верха головы из канона с резом по горизонтали — шов по коже лба;
- перенос по маске волос с раздутием — эхо бровей канона;
- перенос по эрозии маски — тёмная линия по линии роста волос.

Причина: линии роста волос в кадрах не совпадают пиксель в пиксель, а
бесшовная подмена требует совпадения. Вывод: кадры с расхождением
перегенерировать, а не «лечить» композитом. Функция `facefx.keep_hair`
оставлена в коде с предупреждением, в конвейере не используется.
