# 14 · Заготовки ассетов: как больше не генерировать лицо заново

Проблема, которую решает этот документ: при каждой новой позе модель
«придумывает» лицо заново, и герой перестаёт быть похожим на себя. Решение —
**master-файлы + реестр + обязательный QA**. Ниже — как это устроено и как
пользоваться.

## Три уровня ассетов

```
master/    ← источник истины, НИКОГДА не меняется
  turnaround.png   три вида в ряд (фронт / 3-4 / профиль), зелёный фон
  face.png         портрет-идентичность: фронт, нейтральное выражение

views/     ← нарезано из turnaround автоматически (front / three_quarter / side)

pose/, face/  ← производные: генерируются ВСЕГДА с master в референсах
  pose/point.png, pose/wave.png, face/talk_A.png, face/blink.png …
```

Правило: **мастер один раз — производных сколько угодно.** Пока мастер не
изменён, все новые позы будут «тем же человеком».

## Реестр (`studio/characters/registry.json`)

Для каждого героя хранится:

| Поле | Зачем |
|------|-------|
| `desc` | каноническое описание внешности (единый текст для всех промптов) |
| `master.turnaround`, `master.face` | пути к мастерам |
| `derivatives[]` | список производных: имя, путь, статус `ready`/`todo`, **готовый промпт** |
| `fingerprint` | sha256 мастера: если мастер изменился, `verify` это увидит |

Реестр — это машинно-читаемый «чек-лист заготовок». Что не готово — видно
сразу: `derivatives[].status == "todo"`.

## Команды

```bash
# 1. нарезать новые turnaround на виды
.venv/bin/python studio/engine/artgen.py slice

# 2. вырезать всё по хромакею (с despill), мастер-листы не трогаются
.venv/bin/python studio/engine/artgen.py cut

# 3. пересобрать реестр (после добавления героя или новых файлов)
.venv/bin/python studio/engine/artgen.py registry

# 4. контакт-лист на каждого героя: мастер + производные рядом
.venv/bin/python studio/engine/artgen.py sheet

# 5. целостность: мастер не менялся, все ready-ассеты проходят QA
.venv/bin/python studio/engine/artgen.py verify

# 6. авто-QA и отчёт
.venv/bin/python studio/engine/qa.py --assets studio/characters
```

## Как добавить нового героя (например, соседа)

1. Создать папку: `studio/characters/neighbor/{master,pose,face,views}`.
2. Написать `neighbor/character.json`:

```json
{
  "id": "neighbor",
  "label": "Сосед",
  "desc": "a neighbor man, 40 years old, thin, bald spot, round glasses, mustard cardigan, slippers",
  "signature_props": ["round glasses", "mustard cardigan"],
  "palette": {"cardigan": "#D9A441", "skin": "#E0AE86"},
  "forbidden": ["no beard", "no extra limbs"],
  "voice": {"pitch": 1.0, "mood": "доброжелательно-занудный"}
}
```

3. Сгенерировать `master/turnaround.png` (3 вида) и `master/face.png` — все
   производные потом ссылаются на них.
4. `artgen.py slice && cut && registry && verify`.
5. Дальше генерировать позы: промпт берётся из `registry.json`, в референсы
   всегда идут **оба** мастера.

## Как перегенерировать «съехавший» ассет

1. Открыть `registry.json`, найти нужный `derivative.prompt`.
2. Сгенерировать с `master/turnaround.png` + `master/face.png` в референсах.
3. Сохранить поверх старого файла → прогнать QA → посмотреть `_sheet.png`.

Никакой ручной подгонки: расхождение лечится только перегенерацией с мастером.

## Текущий статус заготовок

| Герой | turnaround | face (портрет) | виды (3) | позы | мимика/липсинк |
|-------|-----------|----------------|----------|------|----------------|
| Папа | ✅ | ✅ | ✅ | point ✅ · wave/think/carry/surprise ⏳ | ⏳ |
| Мама | ✅ | ✅ | ✅ | stern ✅ · wave/think/carry/surprise ⏳ | ⏳ |
| Сын | ✅ | ✅ | ✅ | point ✅ · wave/think/carry/surprise ⏳ | ⏳ |

`⏳` — генерируется следующей итерацией: промпты уже лежат в реестре, каждый
ассет — это одна генерация с мастерами в референсах.

## Почему это «профессиональный подход», а не костыль

- **Воспроизводимость.** Любой ассет можно пересобрать из реестра: промпт +
  мастера + постобработка зафиксированы в репозитории.
- **Проверяемость.** `verify` ловит и «мастер изменился», и «ассет не прошёл QA».
- **Масштабирование.** Новый герой — это папка + JSON, а не правка скриптов.
- **Дисциплина.** Пока мастер не изменён, никто не может «случайно» переодеть
  героя или поменять ему причёску: это сразу видно по `fingerprint`.
