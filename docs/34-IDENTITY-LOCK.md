# 34 · Замок идентичности

_Контракт качества промо: кадр героя не рисуется заново. Никогда._

## Правило №0 (после разбора брака)

> **Герой попадает в промо-кадр только вырезанным из мастер-файла.**
> Генерация разрешена для фона, света и реквизита — там, где идентичности нет.

Почему так жёстко. Первая партия промо была сделана «как принято»: герой
описывался текстом, модель рисовала его заново по описанию. Результат — не тот
человек: у папы менялась форма бороды, у мамы лицо становилось моложе и круглее,
у сына терялись черты. Ни один промпт этого не лечит, потому что модель каждый
раз **рисует нового персонажа**, а не воспроизводит вашего. Текстовое описание
задаёт класс объекта («бородатый папа в сером худи»), а не конкретное лицо.

Вывод: идентичность гарантируется только пикселями мастера. Это и есть замок.

| | Было (забраковано) | Стало |
|---|---|---|
| Лицо | «нарисуй папу по описанию» | вырезка из `master-front-v2.png` |
| Пропорции | зависят от генерации | масштаб по канону голов |
| Одежда | переописывается в промпте | та, что на мастере |
| Стиль | уплывает | ровно мастер |
| Доказательство | «на глаз» | `promo_scene.py proof` |

## Что фиксируется, а что меняется

| Фиксируется намертво | Меняется свободно (по команде) |
|----------------------|-------------------------------|
| лицо, причёска, борода, глаза — всё | фон: комната, двор, студия |
| пропорции: папа 5.9 головы, мама 5.7, сын 4.4 | реквизит: коробки, винт, пицца, рамка |
| постоянные элементы: цепочка, `P`, `ABC` | свет и время суток на фоне |
| стиль B (объём, мягкие формы) | композиция: кто где стоит, кроп, формат |
| одежда текущего сезона | одежда **новым мастером** (см. ниже) |

Если надо поменять что-то из левой колонки — сначала перерисовывается мастер в
библиотеке, проходит QA и попадает в `cutouts.json`. Промо никогда не «додумывает»
героя на ходу.

## Библиотека кадров для промо

`studio/promo/canon/cutouts.json` — список того, что можно ставить в кадр:

```bash
.venv/bin/python studio/engine/promo_scene.py list
```

| Ключ | Что | Файл | Источник |
|------|-----|------|----------|
| `dad:front` | стойка, фронт | `2p5d/dad/master-front-v2.png` | мастер ракурса |
| `dad:three-quarter` | три четверти | `2p5d/dad/master-three-quarter-v2.png` | мастер ракурса |
| `dad:side` | профиль | `2p5d/dad/master-side-v2.png` | мастер ракурса |
| `dad:hips` | руки на поясе (визитка) | `2p5d/dad/poses/hands-hips.png` | библиотека поз |
| `dad:point` · `dad:wave` · `dad:facepalm` · `dad:shrug` · `dad:carry` · `dad:sit` · `dad:crouch` · `dad:reach-up` · `dad:phone` | жесты и быт | `2p5d/dad/poses/*` | библиотека поз |
| `mom:stern` | руки скрещены (визитка) | `characters/mom/pose/stern.png` | библиотека |
| `mom:front` · `mom:three-quarter` · `mom:side` | ракурсы | `characters/mom/views/*` | ракурсы |
| `son:point` | палец в камеру (визитка) | `characters/son/pose/point.png` | библиотека |
| `son:front` · `son:three-quarter` · `son:side` | ракурсы | `characters/son/views/*` | ракурсы |

Чего нет в списке — того нет в промо. Нужна поза, которой нет: рисуется кадр в
библиотеку (`studio/2p5d/<id>/poses/` или `characters/<id>/pose/`), проверяется
QA, добавляется в `cutouts.json`. Порядок именно такой.

## Как собирается кадр

```bash
# 1. плата: фон + герои из мастеров (общий случай)
.venv/bin/python studio/engine/promo_scene.py scene --format post-4x5 \
    --cast dad:hips,mom:stern,son:point \
    --bg studio/promo/plates/room-living-empty.png \
    --dad 0.50 --baseline 0.64 --out studio/promo/renders/P01-art.png

# 2. плоская студия (без фона-файла): бумага + шалфейная панель
.venv/bin/python studio/engine/promo_scene.py card dad:front ...   # см. `cards`

# 3. типографика
.venv/bin/python studio/engine/promo.py compose studio/promo/renders/P01-art.png \
    --format post-4x5 --kicker "СЕЗОН 1" --title "…" --out studio/promo/renders/P01-post-4x5.png

# 4. доказательство и приёмка
.venv/bin/python studio/engine/promo_scene.py proof dad:front
.venv/bin/python studio/engine/promo.py verify studio/promo/renders/P01-post-4x5.png
```

Что делает сборщик:

1. **Вырезает** героя: альфа-канал, если он есть; иначе хромакей `#00B140` с
   эрозией края и деспиллом (зелёная кайма убирается: `g ≤ max(r, b)`).
2. **Ставит на общую линию подошв.** В группе высоты считаются по канону голов
   (папа 100 %, мама 96,6 %, сын 74,6 %), соло-кадр масштабируется по кадру.
3. **Добавляет контактную тень** — мягкий эллипс, вписанный по альфе. Без неё
   герой «висит» над полом; с жёсткой маской получается серая плита (проверено).
4. **Не трогает пиксели героя**: никакого перекрашивания, никаких фильтров на
   лице.

Вся партия 1 собирается одной командой — она же печатает метрики и прогоняет
`verify`:

```bash
studio/promo/batch1.sh
```

Кадр собирается детерминированно: один и тот же мастер + одни и те же параметры
дают тот же файл. Поэтому `renders/` можно не хранить в git целиком —
финалы в git лежат как артефакт приёмки, платы (`*-art.png`) пересобираются.

## Доказательство, а не «на глаз»

```bash
.venv/bin/python studio/engine/promo_scene.py proof dad:front --scale 0.84
```

Команда собирает картинку «мастер | то же в кадре» с увеличением лица и считает
совпадение силуэта (IoU). Норма: **99 % и выше** — это одна и та же альфа,
масштабированная. Замер по папе: 99,85 %, по сыну: 99,41 %.

Если IoU упал — значит в кадр попал не мастер (перерисованный файл, другой
ракурс, отражение). Кадр бракуется.

## Фон: единственное место для генерации

Фон генерируется пустым — без людей. `promo.py prompt` теперь собирает именно
такой промпт:

```bash
.venv/bin/python studio/engine/promo.py prompt --format post-4x5 \
    --scene "warm cream living room with plain cardboard boxes, daylight from a window"
```

В промпт всегда входит блок `[EMPTY]`: «no people, no characters, no silhouettes
of people, no text, no letters». Платы складываются в `studio/promo/plates/`.

Правила платы:

1. **Пусто.** Ни одного человека, даже силуэта: иначе героя некуда ставить.
2. **Низ кадра свободен.** Герои стоят на линии подошв, заголовок — ниже неё.
   Для 4:5 — `--baseline 0.64…0.68`, для 9:16 — `0.74`.
3. **Свет как в каноне:** key сверху-слева, мягкие тени.
4. **Никакого текста на реквизите.** Надписи на коробках — брак, как и текст.

## Смена одежды

Одежда меняется **новым мастером**, а не промптом:

1. Описать костюм в `characters/<id>/character.json` → `wardrobe.sets`.
2. Снять мастера ракурсов правкой мастеров канона (меняется только одежда).
3. Прогнать QA библиотеки (`pose_qa.py`, `identity_qa.py`).
4. Заменить файл в `cutouts.json` (или добавить новый ключ, например `dad:front-street`).
5. Старые кадры не удалять: в `cutouts.json` остаются оба костюма, промо берёт
   нужный.

Плюс: ни один кадр при этом не «съезжает», потому что в кадр идут пиксели, а не
описание.

## Приёмка кадра

| Проверка | Допуск | Чем |
|----------|--------|-----|
| Герой = мастер | IoU силуэта ≥ 99 % | `promo_scene.py proof` |
| Порядок в группе | папа · мама · сын | глазами |
| Относительный рост | по канону голов | `lock.json` / линейка |
| Одежда | как на мастере, без «дорисовок» | глазами |
| Реквизит | без надписей и наклеек | глазами |
| Формат, safe-зоны, вес | PASS | `promo.py verify` |
| Текст | только наш слой | глазами |

Чек-лист на каждый кадр (5 секунд):

- [ ] Это то же лицо, что в мастере? (сравнить с `proof`)
- [ ] Пропорции не изменились?
- [ ] Нет лишних рук/пальцев/букв?
- [ ] Ноги стоят на полу, есть тень?
- [ ] Заголовок читается в уменьшении до 120 px?

## Если нужного кадра нет

Три варианта, в порядке предпочтения:

1. **Взять ближайший кадр из библиотеки** (для папы — 49 поз, для мамы и сына
   пока по одной визитке + три ракурса).
2. **Снять кадр в библиотеку**: правка мастера, QA, добавление в `cutouts.json`.
3. **Собрать сцену из композита**: герой из библиотеки + нарисованный реквизит
   слоем (`puppet.py`, `cutout.py`, PIL).

Чего делать нельзя: «попросить модель нарисовать папу в новой позе и вставить в
промо». Именно это и дало брак в первой партии.

## Что меняется в этом документе

Правила и допуски. Источник данных — `studio/promo/canon/cutouts.json` (кадры) и
