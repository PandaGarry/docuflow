# 01 · Стек студии

## Принцип выбора

Нам нужно **повторяемое производство**: одна и та же семья, один стиль, одна
длина серии — 12 раз подряд, без «съехавших» лиц и лишних рук. Поэтому стек
строится вокруг двух идей:

1. **Арт-ассеты дискретны и проверяемы** (PNG-слои, фиксированные палитры,
   жёсткие промпт-шаблоны + автоматический QA).
2. **Анимация — код, а не ручная работа.** Риг и таймлайн живут в репозитории,
   значит серию можно пересобрать и поправить в один клик.

## Выбранный стек

| Слой | Инструмент | Зачем именно он |
|------|-----------|-----------------|
| Генерация арта | image-модель через мультимодальные генерации (референсы семьи → PNG на прозрачном/зелёном фоне) | быстрый продакшн-арт, единый стиль по промпт-шаблонам |
| Чистка арта | PIL: chroma key + despill, `cutout`-пайплайн | убирает зелёный ореол и «мусор» по краям |
| Риг и анимация | собственный движок на Python + numpy: иерархия костей, 2-bone IK, кривые (ease/spring), сквош-стретч, блендшейпы поворотов | полный контроль, детерминизм, версионирование |
| Рендер кадров | PIL (векторные слои, обводки, градиенты) + numpy (композитинг, motion blur, тени) | предсказуемая картинка без GPU |
| Видео | ffmpeg (H.264 High, yuv420p, `+faststart`, CRF 19–21) | универсальная совместимость, малый вес |
| Звук | numpy-синтез музыки/эффектов, TTS для реплик, ffmpeg-микс (`loudnorm -14 LUFS`) | музыка без лицензионных рисков, повторяемость |
| Липсинк | визем-машина: текст → фонемы → виземы → кадры рта | читаемая артикуляция без ручной анимации |
| QA | `studio/engine/qa.py`: контуры, число конечностей, палитра, разрешение, прозрачность, отчёт в Markdown | ловит «третью руку» и «съехавший» цвет до рендера |
| Версионирование | git + JSON-таймлайны серий | каждая серия — данные, а не бинарник |

## Сознательно НЕ используем (и почему)

| Вариант | Почему нет |
|---------|-----------|
| Видеомодели (text-to-video) для финального рендера | нестабильная консистентность героя между шотами, «плывущие» лица и лишние конечности — ровно та проблема, которую мы лечим |
| SVG/векторная анимация (Lottie/AE-экспорт) | требует отдельного редактора в цикле; наш рендер и так детерминирован, а JSON-таймлайн проще ревьюить в git |
| Готовые 3D-пайплайны (Blender) | сильный вариант для стиля B, но на старте это +1 сложный инструмент и +ARMATURE-экспорт; вернёмся, если выберем объёмный стиль |
| Классический cut-out без рига | «прыгающие картинки» — ровно то, что вы забраковали |

## Когда стек стоит расширить

- **Выбран стиль B (объём)** → добавить Blender-пайплайн: арт → 3D-болванка →
  риг → рендер. Наш JSON-таймлайн остаётся, меняется только бэкенд рендера.
- **Серии длиннее 90 с** → вынести рендер на несколько процессов
  (`multiprocessing`, по шотам) — линейно к числу ядер.
- **Нужен дубляж на другие языки** → липсинк-машина уже отделена от таймлайна,
  достаточно заменить аудио и пересчитать виземы.

## Требования к окружению

- Python 3.10+, `pillow`, `numpy`, `imageio-ffmpeg`, `fonttools` (опционально),
  ffmpeg (через `imageio-ffmpeg`).
- Диск: ~200 МБ на сезон (арт + mp4), без учёта промежуточных wav.
- GPU не требуется. Рендер серии 40 с на 6–10 шотах — 3–6 минут на 4 ядрах.
